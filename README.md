# Собрано

**Для Netlify:** используйте отдельную сборку `npm run build:netlify` и папку `.next`. Пошаговая настройка личного входа и хранения данных — [docs/netlify.md](docs/netlify.md). Настройки деплоя уже записаны в `netlify.toml`.

Личное приложение для семейного меню и покупок, версия 0.3. Основной город — Нижний Новгород. Свой интерфейс, название и исходный код; сценарии списков вдохновлены «Всписке».

## Меню и покупки

1. Пользователь заполняет состав семьи, возраст, доли стандартной порции, диеты, аллергии, любимые и исключённые продукты, приёмы пищи дома, бюджет, оборудование, время, готовку на 1–3 дня, магазины, карты лояльности, лимит поездок и запасы со сроками годности.
2. Создаётся недельное меню из 30 встроенных рецептов либо новых рецептов DeepSeek. Блюда приняты по умолчанию, включая меню старой версии. Отдельных согласований в интерфейсе нет.
3. Кнопка «Поменять с ИИ» запрашивает новый рецепт для нужного приёма пищи, учитывает семью, срок хранения партии, ранее отвергнутые названия и доступные цены. Можно менять снова сразу после завершения предыдущего запроса. Замена заготовки действует на все её дни. Неуспешный ответ сохраняет прежнее меню.
4. Покупки пересчитываются после замены. Ингредиенты учитываются на всю партию один раз; домашние запасы вычитаются FIFO с проверкой срока к дню готовки.
5. Сервис сравнивает стоимость целых упаковок и условия скидок, карты, город, срок акции, лимит магазинов и расходы на поездки. Отображаются рекомендуемые сети, сравнение одной закупки в каждом магазине и доля продуктов с найденной ценой.
6. Список создаётся одним действием. Он содержит найденные цены, магазин и ссылку на источник. Неизвестные цены остаются пустыми. При неполной корзине бюджет не объявляется подтверждённым; известная часть сверх бюджета блокирует финализацию. Рецепты сохраняются в личную книгу.

При превышении бюджета подбор вариантов снижает стоимость по доступным предложениям. Это ограниченный поиск среди предложенных рецептов, без гарантии глобального оптимума среди всех возможных блюд.

Общее меню должно подходить всем участникам приёма пищи. Порции задаёт пользователь: это не назначение калорий. Лечебные диеты и питание младенцев до года автоматически не формируются. При аллергиях и строгих ограничениях предложения с неподтверждённым составом не участвуют в расчёте. Условия упаковки и индивидуальные рекомендации специалиста имеют приоритет.

## Источники цен

Сопоставление с ингредиентами использует название и явно опубликованную массу/объём/число штук. Молоко в граммах не заменяет миллилитры, сухие бобовые не заменяют приготовленные, вес с жидкостью не считается слитой массой, готовое блюдо не заменяет сырой ингредиент. Неподтверждённый регион не используется для бюджета Нижнего Новгорода.

Официальные источники, проверенные 14 октября 2026 года:

Это **не полный ассортимент всех восьми сетей**. Проверка доступности без цен не называется синхронизацией. PDF, OCR, эмуляция защиты и изменение сетевого пути не используются. Не применяются цены поискового индекса без подтверждённого города.

Смарт: настоящие публичные JSON GET/POST `WS/hs/exchange`, только штатная ветка `/1/1/1?noauth`, без авторизации. Перед товарами проверяются территория18 и конкретный магазин. Все страницы выбранных категорий читаются обычным размером12, по2 запросам с паузой2 секунды. Берётся видимая обычная `Цена` и единица `ЕдИзм`; неоднозначная `ЦенаСоСкидкой`, `Тег` и `Квант` не превращаются в выдуманные условия акции/покупки. Результат относится к Федосеенко44А, а не ко всем магазинам города. Предложения `official-catalog` являются ориентировочными.

Длинная выгрузка Смарт продолжается короткими запросами: черновик в `catalog_jobs`, источник `continuing`. Частичные товары не попадают в `products` и бюджет. Только после полного чтения выполняется атомарная замена цен и `lastSuccess`; ошибка удаляет черновик, сохраняя прежние предложения. Продолжение выполняется автоматически в открытом планировщике и последовательными POST/GET при фоновом обновлении. Фоновый сбор не блокирует создание меню и работу с блюдами.

SPAR: публичный сервис поиска загружает сам сайт (`search-myspar.ext-geoprod.1221sys.ru`), `location=1510`, запросы по ингредиентам и стандартный лимит15. Куки браузера и данные капчи серверу не передаются. Это часть ассортимента. Индекс и карточка могут показывать разные цены, поэтому `official-search` и бюджет по ним — оценки. Для скидки с неизвестными условиями консервативно требуется выбранная карта; это не подтверждение условия магазина. Весовые покупки учитывают опубликованные минимальный вес и шаг, включая фасованные пакеты.

Сохраняются4 резервных региональных текстовых HTML-каталога Прошопера: Пятёрочка15, Магнит53, Перекрёсток2 подходящих предложения последней успешной выгрузки; SPAR-листовка с изображениями не разбирается. Категория ВкусВилла24 товара без подтверждённого региона исключена из бюджета Нижнего Новгорода. Свежесть48 часов, сроки акций, карты, состав и упаковки проверяются перед расчётом; цена кассы и наличие могут отличаться.

Сравнение показывает все выбранные сети, известную часть суммы и количество ингредиентов без цены. У магазина без котировок сумма `null`, а не0 рублей. Маршрут выбирается сначала по покрытию продуктов, затем по сумме покупок/поездок. Цены каждого SKU рассчитываются один раз и используются во всех сочетаниях магазинов. Для старых профилей/меню НН добавлены запрошенные сети, включая Смарт; после сохранения настройки можно исключить любую сеть. Семья, рецепты, бюджет, сохранённые списки и ключи не изменяются при сборе каталога.

`POST /api/catalog-refresh` обновляет только общую выгрузку всех13 встроенных источников. `GET` возвращает status, lastSuccess, число товаров/регионально подтверждённых предложений каждого источника и общее количество. Для `continuing` повторяется пустой POST и затем GET до завершения. Источники запускаются параллельно, каждый соблюдает свои ограничения; свежие выгрузки не скачиваются снова. База и seed/upsert разбиты на запросы в пределах100 D1 bindings.

Сервисный writer полагается на owner-private доступ Sites. Перед публичным запуском нужен независимый сервисный credential. Токен Sites получают через get_site и используют только в HTTPS-заголовке `OAI-Sites-Authorization` к current_live_url этого сайта, не магазинам; его не сохраняют и не выводят. Доступ только у владельца.

## DeepSeek и приватность

Запросы направляются на версионные адреса `https://api.deepseek.com/v1/models` и `https://api.deepseek.com/v1/chat/completions`. Это обеспечивает корректную авторизацию при проверке ключа и генерации.

Для автоматического серверного подключения поддерживается секрет среды `DEEPSEEK_API_KEY`. При его наличии форма ввода в приложении заменяется информацией о серверном подключении, а генерация использует DeepSeek Flash. Ключ читается только на сервере и не копируется в базу или публичный ответ API. В этом режиме не требуется `AI_SECRET_ENCRYPTION_KEY`. Серверная настройка имеет приоритет над сохранённым личным ключом; её удаление возвращает прежний режим. Предел 100 запросов и исключение параллельных вызовов обеспечиваются атомарным резервированием записи `ai_requests` для обоих режимов.

Поле API-ключа принимает полную строку без фиксированного префикса или предположения о длине ключей провайдера. Внешние пробелы, невидимые символы копирования, парные кавычки и префикс `Bearer` удаляются до проверки. Скрытые/сокращённые значения, адреса сайтов и пробелы внутри ключа дают понятную подсказку без вывода самого ключа. Действительность проверяется запросом к DeepSeek; HTTP 401, 402, 403, 429, таймаут и ошибка соединения различаются. Отказ проверки сохраняет прежний зашифрованный ключ.

Ключ вводится через «Подключить DeepSeek» в самом приватном приложении. Поддерживаются DeepSeek Flash и V4 Pro. Проверка вызывает фиксированный HTTPS `/v1/models`, рецепты — `/v1/chat/completions` с JSON-ответом и отключённым thinking. Ответ проверяется на структуру, разрешённые продукты, количества, ограничения семьи и завершённость. Для замены проверяются приём пищи, срок хранения и отсутствие отвергнутого названия. Имена и email не передаются в рецепты; свободные пожелания не должны содержать личные данные. Запросы оплачиваются с баланса владельца. Лимит — 100 запросов ИИ за 24 часа; атомарная блокировка предотвращает параллельные вызовы и освобождается после каждого ответа.

Каждый рецепт проверяется отдельно: неверная альтернатива не отменяет остальные подходящие блюда. Формат и числовые границы явно передаются модели; обычные десятичные строки преобразуются в числа без угадывания единиц. Если подходящих блюд недостаточно, выполняется одна дополнительная оплачиваемая попытка с описанием ошибок, в пределах общего таймаута 90 секунд. Расход токенов обеих попыток суммируется, дневной лимит учитывает операции пользователя (до двух обращений к провайдеру на операцию). Ошибки авторизации и незавершённые ответы не перезапрашиваются. После неудачной коррекции показывается причина проверки без сырого ответа и секретов; прежнее меню сохраняется.

Ключ хранится как AES-GCM ciphertext с отдельным случайным nonce и owner ID в AAD. Главный 32-байтовый ключ `AI_SECRET_ENCRYPTION_KEY` задаётся секретом среды Sites в Base64 и не хранится в Git. Его нельзя менять без миграции сохранённых ключей. API отдаёт только факт настройки, модель, время проверки и число запросов. Удаление ключа доступно владельцу.

Данные в Cloudflare D1. Сервер проверяет права и версии записей; личные данные изолированы по постоянному непрозрачному ID посетителя. `identity_aliases` поддерживает подтверждённый email без Site-scoped ID и привязку штатного ID при его появлении. Сервисный доступ не подменяет личность пользователя.

Финализация проверяет актуальность профиля и бюджет, резервирует версию меню, сохраняет список, позиции, рецепты и статус транзакцией. Повтор не создаёт второй список. Конфликты возвращают 409. Незавершённое резервирование старше двух минут освобождается.

## Другие возможности

Списки и товары, бюджеты и даты, избранное, приоритеты, отметки покупки, копирование, архив, календарь, собственные рецепты и пересчёт порций, группы owner/editor/shopper/viewer с приглашениями на 7 дней, светлая/тёмная тема, экспорт JSON с параметрами меню без API-ключа, PWA. Расходы считаются по текущим ценам купленных позиций, без банковской интеграции или архива чеков.

Сейчас опубликовано веб-приложение/PWA. В `mobile/` есть каркас Capacitor 8; подписанные Android/iOS-сборки и размещение в магазинах пока не выполнены. Для них нужны аккаунты разработчика владельца, подпись, нативные проекты, проверка авторизации и устройства. Коммерческие платежи пока не реализованы. Совместные группы требуют допуска участников к самому сайту.

## Основной репозиторий

Разработка ведётся в https://github.com/trollpom/family-pokupki, ветка `main`. Перенесён полный снимок исходников опубликованной версии 8: исходный коммит Sites `900a15f7525eea07ac850cfcc708adfea88cad18`. История предыдущего внутреннего репозитория не переносилась.

Перед следующими изменениями обновите локальный checkout из GitHub. Правки, документация и миграции сначала фиксируются здесь; публикация на текущий адрес Sites — отдельный шаг. Сам GitHub не размещает серверную часть и не запускает сборщик цен.

База D1, семейные данные, API-ключи и секреты среды остаются в рабочем приложении. `.openai/hosting.json` сохраняет его идентификатор для дальнейших публикаций и не содержит секретов. Не создавайте новый Site для обновления существующего.

Для локального запуска нужны Node 22.13+ и pnpm из `packageManager`. Установка: `npm run install:ci`; запуск: `npm run dev`; сборка: `npm run build`. Приложение использует Cloudflare Worker и D1, поэтому GitHub Pages не подходит для полноценного размещения. Проверка типов и тесты перечислены выше; тесты интеграции используют отдельную SQLite в памяти. Для локальной проверки сценариев ИИ задайте свой `AI_SECRET_ENCRYPTION_KEY` только в игнорируемой конфигурации среды. Не копируйте и не меняйте секрет рабочего приложения.
